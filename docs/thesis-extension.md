# PDE-TTT thesis code guide

## Repository lineage

This branch starts directly from the final upstream PDE-Transformer commit:

```text
850e09d Update README with P3D reference
```

The commits after that point are intentionally separated into model, data,
training, evaluation, generated-test, and documentation changes. This keeps
the original implementation available for line-by-line comparison during a
thesis defense.

The default thesis branch supports the final method and its matched controls.
Historical temporal-memory experiments are not part of this branch. Early
window-local screening code is retained separately in
`thesis/architecture-screening-legacy`.

## Architecture selection

`PDETransformer` accepts the following `token_mixer_type` values:

| Value | Architecture | Thesis role |
|---|---|---|
| `attention` | Original shifted-window Attention | Matched baseline |
| `global_linear_ttt` | Full-map linear TTT | Selected PDE-TTT method |
| `global_vittt` | Nonlinear full-map ViT3-style TTT | Architecture screen |
| `global_h_vittt` | Periodic RoPE and convolution-enhanced ViT3-style TTT | Architecture screen |

The common PDE hierarchy, conditioning, AdaLN, residual gates, MLPs, skip
connections, and input/output shapes are unchanged. Only the token mixer is
selected by YAML.

The main integration point is
`pdetransformer/core/mixed_channels/pde_transformer.py`. The nonlinear learner
is in `pdetransformer/core/pde_vittt_global.py`; the selected linear learner is
in `pdetransformer/core/pde_vittt_global_linear.py`.

## Selected linear update

For each sample and head, the full stage map is flattened to `N` tokens and
projected to `Q`, `K`, and `V`. A block owns a learned initial matrix `W0` and
constructs a temporary matrix during every forward call:

```text
G      = -(1 / (3N)) K^T V
G_norm = G / (column_norm(G) + 1)
W_fast = W0 - inner_lr * G_norm
Y      = Q W_fast
```

`W_fast` is sample-specific, is never written into the checkpoint, and is
discarded when the block call ends. It does not persist across autoregressive
PDE rollout steps. Every one of the 22 PDE-S blocks owns independent CPE, QKV,
and `W0` parameters.

separate code branches.

## Data and split policy

`pdetransformer/data/pbdl_datatypes/ape_2d_splits.py` defines two explicit
profiles:

- `legacy_small`: the historical 128-resolution architecture screen;
- `full_paper`: the 16-family Full-256 comparison.

For joint 600-simulation files, `full_paper` uses simulations 0--499 as the
train/validation source and 500--599 as strict test. Families with dedicated
`*_test.hdf5` files use those files. Training performs a deterministic 85/15
transition split only inside the train source; strict test simulations are not
included.

The generated ID/OOD matrix is defined by
`pdetransformer/data/simulations_apebench/id_ood_manifest.py` and generated by
`generate_id_ood_testset.py`. It solves at 2048 x 2048, stores 256 x 256
pooled fields, uses three unseen simulation seeds, and evaluates an ID value
plus low/high physical-parameter shifts for 17 PDE families.

## Training

Validate a configuration without reading data:

```bash
python server_example/train_global_vittt_ape_xxl_server.py \
  --config server_example/pdes_global-linear-ttt_256_full.yaml \
  --check-config
```

Validate the required HDF5 files and disjoint split:

```bash
python server_example/train_global_vittt_ape_xxl_server.py \
  --config server_example/pdes_global-linear-ttt_256_full.yaml \
  --check-data
```

Train:

```bash
python server_example/train_global_vittt_ape_xxl_server.py \
  --config server_example/pdes_global-linear-ttt_256_full.yaml
```

EMA-enabled configurations maintain a shadow weight copy after optimizer
steps. Dual-validation runs select `raw-best.ckpt` and `ema-best.ckpt`
independently. EMA does not replace raw weights for the training loss.

## Evaluation and efficiency

`pretrained_eval/test_pretrained_mc_server.py` evaluates Lightning checkpoints,
serialized models, and the public PDE-Transformer safetensors checkpoints. A
strict Full-256 example is:

```bash
python pretrained_eval/test_pretrained_mc_server.py \
  --config server_example/pdes_global-linear-ttt_256_full.yaml \
  --checkpoint-path /path/to/checkpoint.ckpt \
  --data-dir /path/to/pde-transformer-ape2d-full \
  --dataset-profile full_paper \
  --strict-test-split \
  --batch-size 8
```

The evaluator stores per-trajectory, per-family, macro, and micro nRMSE at all
requested horizons. `benchmark/benchmark_p_vs_global_linear_ttt.py` provides
the controlled Attention-versus-PDE-TTT timing and memory benchmark.

## Verification

Focused smoke tests live in `smoke_test/` and cover:

- Attention regression and full-map tensor shapes;
- the closed-form linear update and gradient normalization;
- fast-weight reset, batch independence, outer gradients, and serialization;
- periodic CPE and nonlinear full-map variants;
- explicit train/test simulation identities;
- ID/OOD manifest generation and evaluation;
- raw/EMA update, resume, validation, and export behavior.

Run the focused suite before changing the architecture or experiment YAMLs.
